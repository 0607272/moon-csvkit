# moon-csvkit 项目设计

## 目标

构建一个以 MoonBit 为主要实现语言的 CSV 工具库和命令行工具，解决日常 CSV 检查、格式化及 JSON Lines 转换需求。项目范围必须在 2026 年 9 月 24 日前可完成、可运行、可测试和可复现，并满足 MoonBit 黑客松的公开开发与开源合规要求。

## 用户与使用场景

1. 开发者在提交数据前检查 CSV 的引号、列数和换行错误。
2. 数据处理脚本将 CSV 转为 JSON Lines，供逐行处理或日志管道使用。
3. 开发者将 JSON Lines 转回 CSV，生成可被表格工具打开的文件。
4. 团队通过格式化命令统一 CSV 的换行、转义和表头输出。

## 范围

### 核心库

- RFC 4180 风格的记录解析和序列化。
- 正确处理逗号、双引号、嵌入换行和 `""` 转义。
- 可选表头识别。
- 严格模式：遇到不完整引号、列数不一致等问题返回带位置的错误。
- 宽松模式：尽可能读取输入并报告可恢复问题。
- CSV 与 JSON Lines 之间的转换接口。

### CLI

- `check`：验证 CSV 并输出错误位置。
- `format`：读取 CSV 后按统一规则输出。
- `to-jsonl`：CSV 转 JSON Lines。
- `from-jsonl`：JSON Lines 转 CSV。
- 支持标准输入和标准输出，避免绑定特定操作系统路径。

### 工程交付

- README：目标、安装、命令用法、API 示例、限制和贡献方式。
- 可运行 examples 目录。
- 覆盖核心路径和错误路径的单元测试及集成测试。
- CI：格式检查、构建和测试。
- OSI 认可许可证，并在移植或参考时记录来源。
- MoonBit 包发布配置，目标为 `mooncakes.io`。

## 非目标

- 不实现完整 SQL 查询语言或复杂数据分析引擎。
- 不承诺自动推断复杂类型、日期格式或编码格式。
- 不在第一阶段加入网络服务、图形界面或大规模并行处理。
- 不复制其他 CSV 工具的实现代码；若参考行为，记录来源和许可证。

## 架构

项目分为三个边界：

1. `parser`：字符流到记录的状态机解析，负责语法和错误位置。
2. `codec`：记录、表头和 JSON Lines 之间的结构转换，负责可复用数据接口。
3. `cli`：参数解析、文件/标准输入输出和错误码，依赖前两个模块，不在其中实现 CSV 语法。

解析器采用显式状态机，避免一次性按换行切分导致嵌入换行字段失效。默认 API 返回结构化错误；CLI 将错误转换为用户可读信息和非零退出码。

## 测试策略

- 单元测试覆盖空输入、单列、多列、带引号字段、嵌入逗号、嵌入换行、双引号转义、列数错误和未闭合引号。
- 往返测试验证 `serialize(parse(input))` 在规范化后保持语义一致。
- JSON Lines 转换测试覆盖表头、缺失字段和非法 JSON。
- CLI 集成测试覆盖四个命令、标准输入输出和失败退出码。
- CI 在干净环境执行格式检查、构建和全部测试。
